# Release v0.2.15

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-sugar-valley-neopool/v0.2.15/total?style=for-the-badge)](https://github.com/alexdelprete/ha-sugar-valley-neopool/releases/tag/v0.2.15)

**Release Date:** 2026-03-18

**Type:** Patch release - Fix config flow for fresh installations.

## What's Changed

### Fixed

- **Config flow stuck on fresh install** (Fixes #9): On a fresh Home Assistant
  installation with no prior YAML package, the config flow would get stuck at
  the "Custom Entity Prefix" step with no way to proceed. The setup flow has
  been restructured into two clear steps:
  1. Confirm no active YAML package is running (prerequisite check)
  2. Choose whether to migrate from YAML or set up as fresh installation

  Fresh installs now go straight to device setup. An escape path has also been
  added when the migration path finds no entities to migrate.

  Thanks to **curzon01** for reporting the issue in
  [Discussion #7](https://github.com/alexdelprete/ha-sugar-valley-neopool/discussions/7).

### Added

- **Auto-detection documentation**: New README section explaining how MQTT
  topic detection (wildcard `tele/+/SENSOR`) and entity prefix detection
  (NeoPool signature matching) work, including limitations with multi-level
  custom Tasmota topics.
- **Local brand assets**: Added brand assets for HA 2026.3 brands proxy API.

### Changed

- **Minimum Python version**: Bumped `requires-python` to >=3.13.2 for
  HA 2026.x compatibility.
