# Release v2.2.0-beta.1

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-sugar-valley-neopool/v2.2.0-beta.1/total?style=for-the-badge)][release]

**Release Date:** 2026-10-18

**Type:** Beta release - Tasmota firmware updates from Home Assistant: a new update entity upgrades the Tasmota
device that bridges your NeoPool controller, using NeoPool builds published automatically in this repository.
**Requires Home Assistant 2026.8.0 or later.**

> **This is a beta.** Install it from HACS with "Show beta versions" enabled. Please report problems in the
> [issues][issues].

## What's Changed

### ✨ Added

- **Tasmota firmware update entity.** The device gets `update.<prefix>_tasmota_firmware` (under
  Configuration on the device page). It compares the Tasmota version your device reports with the newest
  NeoPool build in this repository's `firmware/` folder, checked every 6 hours.
  - On **ESP32, ESP32-S3 and ESP32-C3** devices running a NeoPool build (`tasmota32-neopool`,
    `tasmota32s3-neopool`, `tasmota32c3-neopool`), **Install** upgrades the device over the air with Tasmota's
    own `OtaUrl` + `Upgrade 1`. This is a normal upgrade: Wi-Fi, MQTT, templates, rules and every other setting
    are kept. The update shows as in progress until the device comes back with the new version (up to 10
    minutes).
  - **ESP8266** devices and any other build get a read-only entity: it tells you when a new version exists and
    links to the [firmware README][fw-readme] for a manual upgrade.
  - A new Tasmota version is offered **24 hours after it is published**, so it can be tested before it reaches
    everyone.
- **Automated NeoPool firmware builds.** A daily GitHub workflow builds Tasmota with the NeoPool driver for
  ESP8266, ESP32, ESP32-S3 and ESP32-C3 from each new Tasmota stable release, using the build settings from the
  [Tasmota NeoPool documentation][np-docs], and publishes the binaries to `firmware/` with fixed file names. The
  images identify themselves as `tasmota32-neopool` etc., like the hand-made builds by **@curzon01** that
  `firmware/` shipped before. The first automated build is **Tasmota v16.0.0**.

### 🔄 Changed

- **Docs name Tasmota v16.0.0 as the firmware that publishes `Relay.AuxMode`.** **@curzon01**'s driver change
  ([arendst/Tasmota #24998][tasmota-pr]) shipped in Tasmota v16.0.0 (2026-10-16). The README, the MQTT
  reference and the dashboards now say "v16.0.0 or later". No code change was needed for it.

## What to Test

1. **Back up your Tasmota configuration first**: Tasmota web UI → Configuration → Backup Configuration.
1. Open `update.<prefix>_tasmota_firmware`. It should show your installed version and the latest NeoPool
   build. During the first 24 hours after a build is published, both show your installed version.
1. On an ESP32 NeoPool build, press **Install**. The device reboots (about a minute), comes back online and the
   entity reports the new version. All your settings should be unchanged.
1. On Tasmota v16.0.0 or later, the four AUX operating-mode sensors enable themselves once the driver
   publishes `Relay.AuxMode`.

If the device keeps its old version after the install, check the Tasmota console for the OTA log lines and
share them in an issue.

## Upgrade Notes

- **Home Assistant 2026.8.0 or later is required**, same as v2.1.4. Nothing to configure after updating.
- The update entity is a new entity; no existing entity, state or history changes.
- If the entity says your device runs a build that cannot be upgraded from Home Assistant, flash a NeoPool build
  once by hand (see the [firmware README][fw-readme]). From then on, upgrades work from Home Assistant.
