**Release Date:** 2026-08-22

**Type:** Patch release - AUX operating mode pushed by the Tasmota driver (new sensors, keypad-aware AUX
mode selects), plus a major overhaul of the example mushroom dashboards: complete entity coverage,
three-column layout, and conditional sections that adapt to your hardware. No breaking changes.

## What's Changed

### ✨ Added

- **AUX operating-mode sensors.** Four new enum sensors, `sensor.<prefix>_aux1_operating_mode` through
  `aux4`, show each AUX relay's operating mode: **Manual**, **Timer**, or **Countdown**. They read the new
  `NeoPool.Relay.AuxMode` array that **Norbert Richter (@curzon01)** added to the Tasmota NeoPool driver at
  our request ([arendst/Tasmota #24998][tasmota-pr], merged 2026-09-03 into 15.6.0.1), so they need the next
  Tasmota stable after 15.6.0. On older firmware the sensors are disabled automatically rather than left
  unavailable, and they re-enable after a firmware update. Countdown is a mode the integration could not
  see before. Thanks Norbert — discussed in [#16][discussion].
- **AUX mode selects follow the keypad.** When `Relay.AuxMode` is present, the `aux<n>_mode` selects derive
  their option from the pushed mode plus the physical relay state (Timer → Auto, Manual + on/off → On/Off),
  so a mode change made at the controller shows up at the next telemetry, no polling. Older firmware keeps
  the previous behaviour (read once at startup, kept current by the integration's own writes). All four
  example dashboards gained "Aux1..4 Op. Mode" tiles next to the AUX mode selects.

### 🔄 Changed

- **The mushroom dashboards now cover every entity the integration ships.** A full audit against the entity
  inventory added the last 13 missing tiles, each in its logical place:
  - A **Filtration Status** row under Main Controls with the telemetry-reported Mode / Speed / Boost sensors
    ("Filtr. Mode Status", "Filtr. Speed Status", "Hydro Boost Status") — these show what the controller is
    actually doing, which can diverge from the command selects when the physical panel is used. The status
    row sits above the selects so each column reads as a status/command pair.
  - **Hydrolysis Shutdown Temperature** beside its Temp Shutdown switch in Configuration.
  - **Setpoint g/h**, **Max Prod.**, **Unit**, **Part. Runtime**, and a confirmation-guarded
    **Reset Runtime** button in Hydrolysis Module Info.
  - **Powerunit Version** in Power Unit Info; **System Model** and **System ID** in Controller.
- **The dashboards adapt to your hardware via conditional sections.** Tiles for hardware you don't have no
  longer render as dead cards:
  - A conditional **Heating** section (Climate Mode, Heating Temperature, Intelligent Min Filtration Time)
    renders only when the controller has a heating relay assigned — per the Tasmota driver register map,
    Intelligent filtration mode itself requires the heating function.
  - A conditional **UV** section (UV Mode switch) renders only when a UV relay is assigned.
  - Each of the six **Relays State** tiles (Acid, Base, Redox, Heating, UV, Valve) hides individually when
    its relay function is not assigned — the integration disables those entities dynamically, and the
    dashboard now follows.
- **Three-column layout, grouped by purpose.** The two masonry stacks are now three: *Monitor & Control*
  (readings + graphs, Main Controls, Setpoints, Configuration), *Status & Modules* (Alarms at the top so
  problems are visible without scrolling, then Hydrolysis Module Info, the conditional module sections,
  Modules Detected, Relays State, AUX Relays Mode), and *Schedules & System* (Timer Schedules, Controller,
  Power Unit Info, Connection Statistics).
- **More of the integration surfaced.** The Timer Schedules section shows each filtration timer's per-timer
  Speed select (rows are Mode / Speed / Start / Stop); the AUX Relays Mode row gained AUX1–4 relay state
  indicators above the mode selects; and a new Configuration section exposes the register-backed tuning
  knobs that previously lived only on the device page: pH Pump Delay, Cover Reduction (switch + %),
  Temp Shutdown (+ its temperature), Smart Antifreeze, and Auto Time Sync.
- **New "Alarms" row groups all six problem-class tiles**, state-colored (green OK, red alarm): Hydro Flow
  Alarm, pH Flow Alarm, Low Production, pH Tank, Redox Tank, and the Connection Health tile — renamed
  **Controller Link**, since it watches the RS-485/Modbus link to the NeoPool board. The pH Flow Alarm and
  the two tank-level sensors got dashboard tiles for the first time; the tank tiles tell you when a reagent
  canister needs refilling. Icons identify the circuit instead of repeating an alert glyph, and each tile
  sets `tap_action: more-info` explicitly (the legacy template card's default tap is `toggle`, which is
  invalid for binary sensors).
- **Clearer tile names**: "Mode" → "Filtr. Mode", "Speed" → "Filtr. Speed", "Boost" → "Hydro Boost" (it is
  the hydrolysis boost), and the AUX mode selects → "Aux1 Mode".."Aux4 Mode" to distinguish them from the
  adjacent Aux state tiles.
- **Problem tiles render correctly under Mushroom themes.** All state-colored tiles use
  `mushroom-legacy-template-card`: in Mushroom v5 the new `mushroom-template-card` is rebuilt on HA's native
  tile card and is not compatible with Mushroom themes (it lost the icon shape background under themes like
  Mushroom Square); the legacy card keeps the classic rendering and matches the surrounding tiles. No new
  card dependency.

The dashboard changes above apply to `ha_neopool_lovelace.yaml` and `ha_neopool_lovelace_migrated.yaml`;
the responsive dashboards only gained the AUX operating-mode tiles.

## Upgrade Notes

Updating is safe and requires no action. The new AUX operating-mode sensors appear (enabled) as soon as your
Tasmota build publishes `Relay.AuxMode` (15.6.0.1 or later); until then they stay disabled on the device
page. To get the new dashboards, re-import the dashboard YAML for your install type (fresh vs migrated)
from the `lovelace/` folder; see `lovelace/README.md` for the selection logic and custom-card dependencies.
