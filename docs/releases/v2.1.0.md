# Release v2.1.0

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-sugar-valley-neopool/v2.1.0/total?style=for-the-badge)][release]

**Release Date:** 2026-08-19

**Type:** Minor release - Cleans up the configuration entities introduced in v2.0.0: they now populate reliably at
startup, entities for hardware you don't have are hidden instead of shown as unavailable, and the bundled
dashboards reference the correct timer entities. No breaking changes.

## What's Changed

### 🔄 Changed

- **Config entities for hardware you don't have are now disabled instead of shown as perpetually unavailable.**
  The heating/UV config controls (Climate Mode, Heating Temperature, Intelligent Minimum Filtration Time, UV
  Mode) and the hydrolysis/pH config controls now follow the same runtime enable/disable mechanism already used
  for the relay-state and module sensors: they are disabled when their relay/module is absent from the telemetry
  and automatically re-enabled if it later appears. This keeps the device page clean rather than listing
  controls that can never work on your installation. Entities you disabled yourself are left untouched.

### 🐛 Fixed

- **Register-backed config entities no longer stay unavailable after startup.** The integration reads the
  config/timer registers that are not in the SENSOR telemetry with a series of `NPRead` commands at startup; the
  controller drops reads that arrive as one fast burst, so the earliest registers went unread and their entities
  (UV mode, climate mode, smart antifreeze, heating temperature, intelligent minimum filtration time, pH pump
  activation delay, hydrolysis cover/shutdown, and the four AUX mode selects) stayed `unavailable`. The reads
  are now paced and run in the background, so these entities populate shortly after startup. This regressed in
  v2.0.0 when the new per-timer registers enlarged the startup read burst.
- **Bundled Lovelace dashboards referenced the wrong per-timer entity IDs.** The timer tiles used
  `..._filtration_timer1_mode` and similar, but Home Assistant slugifies the entity IDs as
  `..._filtration_timer_1_mode` (underscore before the digit), so the twelve timer tiles were dead on a freshly
  pasted dashboard. All four bundled dashboards now use the correct entity IDs.
- **Auto Time Sync switch now shows an icon.** Its configured icon (`mdi:clock-sync-outline`) is not a valid
  Material Design Icons name, so the frontend rendered no icon; it now uses `mdi:update`.

## Upgrade Notes

No action required. After updating, the config entities for modules/relays your controller doesn't have will
disappear from the device page (they were unavailable before). If you had pasted a bundled dashboard from
v2.0.0, re-copy the timer section (or the whole dashboard) to pick up the corrected timer entity IDs.
