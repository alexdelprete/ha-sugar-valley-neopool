# Release v0.2.17

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-sugar-valley-neopool/v0.2.17/total?style=for-the-badge)](https://github.com/alexdelprete/ha-sugar-valley-neopool/releases/tag/v0.2.17)

**Release Date:** 2026-04-03

**Type:** Patch release - Fix Modules JSON path, add entity availability logic,
add 7 named relay binary sensors, fix legacy entity cleanup.

## What's Changed

### Added

- **7 new named relay binary sensors**: Base, Redox, Chlorine, Conductivity,
  Heating, UV, Valve (`NeoPool.Relay.*`). These report logical function status
  regardless of physical relay assignment. Includes translations for all 10
  languages and custom icons.

### Fixed

- **Modules JSON path**: The JSON key for module presence in SENSOR telemetry
  is `Modules` (plural), not `Module` (singular). Confirmed by Tasmota source
  code (`D_NEOPOOL_JSON_MODULES = "Modules"`), real device payloads, and the
  upstream YAML package. The v0.2.16 change to singular was incorrect.
- **Entity availability AND logic**: Entities are now correctly marked
  unavailable when their JSON key is absent from the MQTT payload. Previously,
  absent keys were silently ignored, leaving entities available with stale data.
  This implements the correct condition: entity available only when device is
  online (LWT) AND JSON key is present. Applied to all entity platforms.
- **Legacy entity cleanup**: The deprecated entity removal now also handles
  the legacy unique_id format (without NodeID) used by YAML-migrated entities,
  fixing ghost entities reported by Spook on systems that migrated from the
  YAML package.

### Changed

- Updated `docs/ha_neopool_mqtt_package.yaml` to upstream v4.0.

## Acknowledgments

on relay availability behavior and confirming the `Modules` JSON key naming.
