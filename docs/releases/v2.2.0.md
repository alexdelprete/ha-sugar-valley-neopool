# Release v2.2.0

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-sugar-valley-neopool/v2.2.0/total?style=for-the-badge)][release]

**Release Date:** 2026-10-18

**Type:** Minor release - Tasmota firmware updates from Home Assistant, automated NeoPool firmware builds, and a
fix that **v2.1.3 / v2.1.4 users need before upgrading Tasmota to v16.0.0**. **Requires Home Assistant 2026.8.0 or
later.**

> **Running Tasmota v16.0.0 with v2.1.3 or v2.1.4?** Those versions go into an endless reload loop as soon as the
> device runs Tasmota v16.0.0: the NeoPool entities keep flickering unavailable and the log fills with "Re-enabled 4
> previously-disabled entities, scheduling integration reload". Update to this release. If Home Assistant is too
> busy to update, disable the NeoPool integration first (Settings → Devices & services), update, restart, and
> enable it again.

## What's Changed

### ✨ Added

- **Tasmota firmware update entity.** The device gets `update.<prefix>_tasmota_firmware` (under Configuration on
  the device page). It compares the Tasmota version your device reports with the newest NeoPool build in this
  repository's `firmware/` folder, checked every 6 hours.
  - On **ESP32, ESP32-S3 and ESP32-C3** devices running a NeoPool build (`tasmota32-neopool`,
    `tasmota32s3-neopool`, `tasmota32c3-neopool`), **Install** upgrades the device over the air with Tasmota's
    own `OtaUrl` + `Upgrade 1`. This is a normal upgrade: Wi-Fi, MQTT, templates, rules and every other setting
    are kept. The update shows as in progress until the device comes back with the new version (up to 10
    minutes; the device reboots twice, once into Tasmota's safeboot image that flashes the new firmware).
  - **ESP8266** devices and any other build get a read-only entity: it tells you when a new version exists and
    links to the [firmware README][fw-readme] for a manual upgrade.
  - A new Tasmota version is offered **24 hours after it is published**, so it can be tested before it reaches
    everyone. Tasmota v16.0.0 is offered from 2026-10-19 19:54 UTC.
- **Automated NeoPool firmware builds.** A daily GitHub workflow builds Tasmota with the NeoPool driver for
  ESP8266, ESP32, ESP32-S3 and ESP32-C3 from each new Tasmota stable release, using the build settings from the
  [Tasmota NeoPool documentation][np-docs], and publishes the binaries to `firmware/` with fixed file names. The
  images identify themselves as `tasmota32-neopool` etc., like the hand-made builds by **@curzon01** that
  `firmware/` shipped before. The first automated build is **Tasmota v16.0.0**.

### 🐛 Fixed

- **Endless reload loop on Tasmota v16.0.0** (affects v2.1.3 and v2.1.4). Tasmota v16.0.0 is the first stable
  release that publishes `Relay.AuxMode`. The integration's startup check did not record it while its live
  telemetry watch did, so every startup disabled the four AUX operating-mode sensors, the watch re-enabled them on
  the next message and reloaded the integration, and the reload started over: about two reloads a second, each
  re-reading the controller's registers. Both now use the same list, and the AUX operating-mode sensors come up
  enabled on v16.0.0.
- **Firmware update entity: a failed check is retried after 5 minutes.** The first check runs while Home
  Assistant is still starting and can time out; the entity then stayed unavailable for 6 hours.
- **Firmware update entity: no "safeboot build" during an upgrade.** While Tasmota's safeboot image flashed the new
  firmware, the device page and the entity briefly showed the safeboot version as the device's firmware. The
  previous version is now kept until the device reports in on the new one.

### 🔄 Changed

- **Docs name Tasmota v16.0.0 as the firmware that publishes `Relay.AuxMode`.** **@curzon01**'s driver change
  ([arendst/Tasmota #24998][tasmota-pr]) shipped in Tasmota v16.0.0 (2026-10-16). The README, the MQTT reference
  and the dashboards now say "v16.0.0 or later".

## Upgrade Notes

- **Home Assistant 2026.8.0 or later is required**, same as v2.1.4. Nothing to configure after updating.
- **Before pressing Install, back up your Tasmota configuration**: Tasmota web UI → Configuration → Backup
  Configuration.
- The update entity is a new entity; no existing entity, state or history changes.
- If the entity says your device runs a build that cannot be upgraded from Home Assistant, flash a NeoPool build
  once by hand (see the [firmware README][fw-readme]). From then on, upgrades work from Home Assistant.
- On Tasmota v16.0.0 the four AUX operating-mode sensors enable themselves.
